# 数据采集以覆盖面与正文质量为优先，不设合规边界

JobE 的能力图谱与演化分析都吃职位正文。人社部列表没有 JD、Moka 只有约 20 家企业、猎聘默认关闭——这三条把生产数据卡死在「有量无正文」或「有正文无量」。本决策把采集边界从「合法来源为主干、商业平台只做小样本」改成「凡是能稳定拿到带正文、带时间戳的职位，一律接入」。不评估用户协议、robots.txt、反爬判例，也不把「不突破技术措施」当作约束。

## Decision

1. **来源清单开放。** 人社部、Moka、猎聘、BOSS 直聘、Greenhouse / Lever / Ashby 等 ATS 公开接口、jobhive 托管的北森与 Moka 中国切片，都可以进主干。不采用 Job-SDF / Chinese-SkillSpan（公开仓没有技能名称表、没有带正文的历史 JD，也不做演化时序导入）。新增来源只看四件事：能否拿到职位描述正文、是否有可解析的发布时间、能否落到不可变快照、字段能否映射到 `Posting`。
2. **不做合规限制。** 采集器可以走登录态、CDP、内部 wapi、签名参数、验证码后的会话。频控只为降低封禁与空响，不是法律义务。`requires_login` 仍保留，只表示工程上要不要 Cookie / 浏览器，不表示「默认关闭」。
3. **快照契约不变。** 任何来源先落 `snapshots`，分析层只读快照。第三方复现结论时不需要再打目标站。
4. **PII 仍丢。** 联系人姓名、电话、邮箱、微信不进快照。这是图谱用不上这些字段，不是合规条款。
5. **商业数据包不做。** Bright Data、Coresignal 一类付费库不接入，成本与字段不可控。

## Considered Options

维持 ADR 原文（合法主干 + 猎聘小样本）被否决：技能抽取几乎只能靠 Moka，演化分析没有历史轴，多源去重也无从谈起。只扩 Moka org、不碰招聘网站被否决：Moka 覆盖的是用了该 ATS 的企业子集，对国内互联网岗位代表性不够。买商业数据包被否决：见第 5 条。

## Consequences

- `collectors/` 可以增加 BOSS、海外 ATS、数据集导入器；`sources.py` 是来源登记的唯一入口。
- 猎聘、BOSS 不再「默认永久关闭」。开关变成运行时配置（环境变量），开发默认关是为了测试不打真实站，生产采集按需打开。
- 演示与评测不再承诺「未突破技术措施」。文档与 README 按本 ADR 表述。
- 封号、验证码、接口改版是运维问题，用专用账号、失败即停、快照隔离处理，不因此砍来源。
