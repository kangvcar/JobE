# 职途罗盘 JobE

多源异构数据驱动的岗位能力图谱与动态演化分析。JobE 取 **Job Evolution**——这套系统的核心不是给岗位拍一张静态照片，而是持续测量岗位的能力要求如何随技术演进而变化，并把这个变化翻译成个人可执行的下一步。

面向的第一用户是新兴领域的青年与在校学生：上传简历，看到自己与目标岗位的真实差距，以及这个差距因为市场变化正在如何移动。

## 它解决什么

招聘数据有三个众所皆知却少有人处理的毛病：**时滞**（职位反映的是半年前定下的需求）、**噪声与抄袭**（同一份职位跨平台重复投放、同行互抄，朴素词频会把抄袭读成需求上升）、**技能通胀**（要求逐年膨胀而工作内容没变）。绕不开这三件事，任何"岗位能力分析"都只是把噪声画成图。

JobE 的做法是：技术信号（开源仓库、论文、包下载量、模型发布）在时间上领先于招聘需求，这个领先滞后期是可实测的参数而非假设；一旦测出来，"某技术爆发后新兴岗位会长出哪些能力要求"就从事后描述变成了可预测量。

## 三条不让步的规矩

1. **没有证据的结论不进图谱。** 每个技能点、每次能力变更都携带原文片段、来源和采集时间，能在原始文档上高亮定位。
2. **大模型不产出位置。** 它只做语义判断，字符区间与版面坐标一律由确定性字符串匹配回填；匹配不上即判抽取失败并丢弃——这条规则本身就是幻觉过滤器。
3. **分析只读快照。** 采集结果一经落库不再修改，任何人在无网络环境下都能复现全部结论。

## 快速开始

```bash
cp .env.example .env      # 填入 LLM_API_KEY
docker compose up -d
```

后端 <http://localhost:8000/docs>，前端 <http://localhost:5173>，Neo4j 浏览器 <http://localhost:7474>。

本地开发后端：

```bash
cd backend
uv sync
uv run uvicorn app.main:app --reload
uv run pytest
```

## 数据来源与合规

主干数据来自人社部中国公共招聘网、Moka ATS 公开接口、Job-SDF 与 Chinese-SkillSpan 等合法来源；商业招聘平台仅做小样本、人工登录、低频只读的采集，不突破任何技术措施，不采集任何个人信息。取舍理由见 [ADR 0001](./docs/adr/0001-data-collection-boundary.md)。
