# 匹配档位判定准则

版本：1.0  
适用范围：人岗匹配评测的金标准。系统输出与本准则同档即算正确。  
读者：标注员。四档名称与 `CONTEXT.md`、领域模型 `MatchTier` 对齐：高度匹配 / 基本匹配 / 有明显差距 / 不匹配。

技能点是否存在、如何切分，一律先按《技能点切分准则》完成。本准则在已经切好的技能点集合上做档位判定。

---

## 1. 四档定义（先建立直觉）

| 档位 | 枚举值 | 一句话 | 候选人侧可执行含义 |
| --- | --- | --- | --- |
| 高度匹配 | `strong` | 核心必备几乎都满足，方向对，门槛够 | 可直接进面试，差距可忽略 |
| 基本匹配 | `adequate` | 方向对，缺少量可补的必备技能 | 可面试，需要 3–6 个月补齐 |
| 有明显差距 | `gapped` | 同方向但关键缺口明显 | 需要系统学习，不是「再刷两周题」 |
| 不匹配 | `mismatch` | 方向不对，或覆盖过低 | 不应作为该岗位的有效候选人 |

真实招聘里「有明显差距」最多，其次「基本匹配」。金标准的档位分布应接近这个形状，**禁止**为了指标好看把 gapped 抬成 adequate。

## 2. 判定前必须先算出的量

对每一对「技能画像 × 岗位」计算下列量。符号固定，标注说明里要写出来，便于抽检。

**技能范围**

- 岗位技能点来自 JD 金标准。
- **核心必备** `R`：`necessity = required` 且 `family ≠ soft` 的技能点集合。若 `R` 为空，则退化为全部非软技能。
- **方向性必备** `D`：`R` 中 `family` 等于该岗位族（人工智能 / 大数据 / 智能系统 / 物联网）的技能点。`family = general` 的不算方向性。
- **画像技能** `H`：简历金标准中的技能点，带水平 `level ∈ {0,1,2,3}`（0 未掌握，1 了解，2 能独立交付，3 能设计/带人）。
- 软技能不进入覆盖率，也不进入档位规则。它们只出现在技能点抽取评测里。

**是否满足一条必备技能**

- 规范名相同（大小写不敏感，去首尾空白）视为同一技能点。
- `held_level ≥ required_level` 才算满足。`required_level` 缺省：必备为 2，加分为 1；JD 写「精通/专家」则为 3，「了解」则为 1。
- 在画像中出现但水平不够 → 记为 **不足**（`insufficient`），**不算覆盖**。
- 不在画像中 → **缺失**（`missing`）。
- 满足 → `satisfied`。
- 画像有、岗位无 → **冗余**（`surplus`），不影响档位，计入差距明细。

**三个比率**

- 覆盖率 `c = |satisfied ∩ R| / |R|`。`R` 为空时令 `c = 1`（不应发生，发生则记异常）。
- 方向覆盖率 `c_dir = |satisfied ∩ D| / |D|`。`D` 为空时令 `c_dir = 1`。
- 方向缺失数 `n_dir_miss = |D − satisfied|`。

**门槛**

- 学历序：不限 < 大专 < 本科 < 硕士 < 博士。画像 ≥ 岗位要求视为学历满足。岗位未写则视为满足。
- 经验：取岗位 `min_experience`（年）。画像工作年限 ≥ 该值视为经验满足。岗位未写则视为满足。应届岗位对年限视为满足。

**岗位族错位**

- 简历主方向 = 画像中非 general、非 soft 技能点出现次数最多的 `family`；并列时取与岗位族相同的那个，否则取字母序第一个。
- 若简历主方向 ≠ 岗位族，且 `c_dir < 0.20`，则判定为岗位族错位。

## 3. 档位规则（按顺序，先命中先结束）

标注员**不要凭感觉跳步**。必须按 R1 → R7 逐条问。

**R1 岗位族错位 → 不匹配**  
简历主方向与岗位族不同，且方向覆盖率 < 0.20。

边界：Python + Linux + Git 的后端简历投「视觉算法」岗位，即使这三项都命中，只要方向性技能（OpenCV / 目标检测 / PyTorch 等）覆盖 < 20%，仍是不匹配。不要因为通用栈重合抬档。

**R2 覆盖过低 → 不匹配**  
`c < 0.30`。

**R3 覆盖偏低且门槛全不满足 → 不匹配**  
`c < 0.40`，并且学历、经验都不满足。

**R4 高度匹配**  
同时满足：

- `c ≥ 0.90`
- `n_dir_miss = 0`
- 学历、经验至少一项满足

允许：加分项大量缺失；一两项 general 技能不足（但不得是方向性必备）。

**R5 基本匹配**  
同时满足：

- `c ≥ 0.70`
- `n_dir_miss ≤ 1`
- 未命中 R1–R3

允许：缺 1 个方向性必备，或若干 general 必备；学历或经验差一档。

**R6 有明显差距**  
`c ≥ 0.40`，且未命中 R1–R5。

典型：同方向，缺 2 个以上方向性技能；或覆盖率在 40%–70%。

**R7 其余 → 不匹配**

## 4. 技能级判定明细（必须随档位一起给）

每一条岗位技能点（含加分、不含软技能）输出一条：

```text
skill_name | required(true/false) | verdict(satisfied|insufficient|missing)
```

评测「技能级判定准确率」按这些原子判断计，不按档位计。档位对了但某条技能判错，技能级准确率仍会扣分——这是用来解释「错在哪个技能上」的。

冗余技能写入 `surplus` 列表，不进入技能级准确率的分母。

## 5. 边界案例（标注员必读）

### B1 覆盖率卡在阈值上

`c = 0.70` 且 `n_dir_miss = 1` → **基本匹配**（R5 含等号）。  
`c = 0.69` → 不能进 R5；若未命中 R1–R4 则 **有明显差距**。  
禁止「四舍五入到 70%」。覆盖率保留四位小数，比较用 ≥ / <，不用约等。

### B2 技能全有但水平全是 1

画像「都听说过」，岗位必备要求默认水平 2。则 `satisfied` 为空或很少，`insufficient` 很多。按覆盖率走：多数会落到有明显差距或不匹配。**不要**因为「名字都对上了」标成基本匹配。

### B3 方向对，经验差很多

5 年经验要求的专家岗，应届简历 `c = 0.85`、`n_dir_miss = 0`。经验不满足，但 R4 要求「学历与经验至少一项满足」——若学历满足，仍可高度匹配；若学历也不满足，R4 不命中，看 R5：`c ≥ 0.70` 且方向缺失 ≤ 1 → **基本匹配**。  
经验差不应单独把人打成不匹配（除非同时触发 R3）。

### B4 通用栈重合、方向不对

见 R1。再举一例：大数据开发简历（Spark/Hive/Kafka）投物联网嵌入式岗（STM32/RTOS/MQTT）。即使两边都有 Linux，方向覆盖通常 < 20% → **不匹配**。

### B5 加分项全中、必备缺很多

加分项不进入 `c`。必备覆盖 35% → **不匹配**（R2）或 **有明显差距**（若 ≥ 40%）。不允许用加分项「拉」档位。

### B6 同一技能别名

JD 写「Pytorch」，简历写「PyTorch」→ 同一技能点，判定为满足（若水平够）。别名以切分准则词表为准。

### B7 岗位族内换方向

「NLP 算法」简历投「推荐算法」岗，同属人工智能。R1 不触发（主方向同族）。按覆盖率和方向性缺失数走：若推荐方向性技能（召回、排序、特征工程等）缺 2 个以上，通常是 **有明显差距**，不是不匹配。

### B8 必备集合很小

岗位只写了 3 条必备（Python、Linux、通信原理）。缺 1 条则 `c = 0.67` → 有明显差距，即使另外 20 条加分全中。小必备集合对单条缺失更敏感，这是规则本身的性质，不要手改档位。

### B9 扫描件 / 抽取失败的技能

匹配金标准用**简历技能金标准**，不用系统抽取结果。评测匹配时，假设画像已给定。系统若先抽错再匹配，错会同时反映在抽取指标和匹配指标上——这是预期，不要在匹配金标准里「迁就」抽取错误。

## 6. 排序标注（一份简历 × 10 个岗位）

1. 先对 10 个岗位各自给出档位与覆盖率。
2. 排序键，从高到低：档位（strong > adequate > gapped > mismatch），档位相同则覆盖率高者在前，再相同则 `n_dir_miss` 少者在前，再相同则按岗位 id 升序（保证可复现）。
3. 标注员若认为规则排序「直觉不对」，**先检查切分是否错**，不要直接改序。只有发现规则未覆盖的新边界时，才提交准则修订；修订前的批次保持原金标准。

---

## 7. 禁止事项

- 禁止根据公司名气、薪资高低改档位。
- 禁止因为「这个人挺聪明的」抬档。
- 禁止为了让系统指标好看而改金标准。金标准是裁判。
- 禁止两人商量后再标。独立标注，再算 κ。
- 档位 κ 的计算单位是「简历×岗位」对，四类名义变量。

---

## 8. 与差距三类的关系

档位判定之后，差距明细仍按 `CONTEXT.md` 的三类书写，供诊断评测（本评测集的匹配主指标不直接打差距分类准确率，但每对金标准带上，便于后续扩展）：

- `missing`：必备或加分技能点不在画像中。
- `insufficient`：在画像中但水平低于要求。
- `surplus`：在画像中但不在岗位技能集合中。
